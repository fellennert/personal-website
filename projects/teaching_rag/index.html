A Local RAG Assistant for Teaching Materials

Author

Felix Lennert

Published

February 11, 2026

Description and motivation

Teaching Computational Social Science means juggling a lot of moving parts: weekly slides, code-heavy handouts, assignment descriptions, and project guidelines. Students often have very specific questions (“Where did we talk about supervised vs. unsupervised learning?” or “What exactly did you say about OCR vs. Whisper?”) that are answered somewhere in the materials, but not always easy to find on short notice. Rather than sending them back to a generic chatbot, I built a Retrieval-Augmented Generation (RAG) system that knows only about my course and answers questions based strictly on the resources I gave them.

I packaged this into an R package called teachrag, available on GitHub. It uses the ragnar package to turn course materials into a searchable store, connects to Ollama (local) or Claude (API) for answers, and includes a Shiny app and setup wizard for interactive use.

Data source

The underlying corpus consists of teaching materials for a semester-long Computational Social Science toolbox course:

  • The syllabus (syllabus/, with reading lists and policies)
  • Lecture slides (slides/, PDFs for intro, crawling, scraping, OCR/Whisper, Text as Data I–V)
  • Topic-specific notebooks (script/, Quarto files such as 14_supervised_ml.qmd, 17_BERT.qmd, 18_GPT.qmd)

For copyright and privacy reasons, the underlying materials are not published here. The corpus lives in files_for_project_backlog/teaching_rag/course_material/ for local use.

The teachrag package

The package provides:

  • Parse and build: parse_materials() converts documents to markdown and chunks; build_store() creates a DuckDB-backed ragnar store with nomic-embed-text embeddings
  • Single-turn Q&A: ask_rag() retrieves relevant chunks and sends them to an LLM (Ollama or Claude)
  • Multi-turn chat: ask_rag_chat() maintains conversation state and retrieves fresh chunks for each question
  • Shiny app: Interactive Q&A with backend choice (Ollama/Claude) and conversation history
  • Setup wizard: A Shiny wizard guides first-time setup (paths, parse, build, test)

Setup and first run

Show code 
library(teachrag)

# Option 1: run the setup wizard (recommended for first-time setup)
run_setup_wizard()

# Option 2: set paths manually and run steps
corpus_dir <- "path/to/course_material"   # syllabus/, slides/, script/
output_dir <- "path/to/intermediate"

parse_materials(corpus_dir = corpus_dir, output_dir = output_dir)
build_store(output_dir = output_dir)

options(
  teachrag.store_path = file.path(output_dir, "teaching_db.ragnar.duckdb"),
  teachrag.intermediate_dir = output_dir
)

# Single-turn Q&A
ask_rag("What is supervised machine learning?")

# Multi-turn chat
chat_state <- NULL
res <- ask_rag_chat(chat_state, "What is supervised ML?")
chat_state <- res$chat_state
ask_rag_chat(chat_state, "Can you give an example?")

# Shiny app
run_app()

Architecture

The pipeline:

  1. Parse: Discover files (qmd, Rmd, md, pdf), convert to markdown via ragnar::read_as_markdown, chunk by doc type (slides by " --- ", scripts by "##" and "###"), write syllabus.rds and chunks.rds to the output directory.

  2. Build store: Read chunks, reformat for ragnar, create DuckDB store with nomic-embed-text embeddings via Ollama.

  3. Query: ask_rag() retrieves relevant chunks with BM25, formats context, sends to the LLM; a content checker ensures answers stay within scope using the syllabus summary.

  4. Multi-turn: ask_rag_chat() keeps the same chat session and retrieves fresh chunks for each follow-up question so answers stay aligned with course content.

Requirements

  • Ollama with qwen2.5:3b and nomic-embed-text
  • For Claude: ANTHROPIC_API_KEY in the environment
  • R packages: dplyr (>= 1.2.0) and others (see DESCRIPTION). Run teachrag::check_dependencies() to verify.

Summary

This project turns a semester’s worth of teaching materials into a focused RAG system. Using ragnar, I ingest heterogeneous documents, chunk them along meaningful headings, and store them in a DuckDB-backed vector index with embeddings from a local model. The teachrag package wraps this with a Shiny app, setup wizard, and multi-turn chat—so students (and I) can ask natural-language questions and get grounded answers that cite where in the course the information comes from.

The system is intentionally modest: it does not try to be a general-purpose assistant, but rather a guided search and explanation tool over a well-defined corpus. The code is available as an R package on GitHub.
